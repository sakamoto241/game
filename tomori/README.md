# 勇者の剣、売りました。

昨日300Gで売った剣が、今日1億Gになっていた。代金は四人の夕食へ。古道具屋リネたちが買い手を追いかけ、聖剣を取り戻すコマンドRPGです。第一章「食べた300G」を収録しています。

## 起動

リポジトリのルートで `python3 -m http.server 8006` を実行し、`http://localhost:8006/tomori/` を開きます。外部ライブラリ・バックエンド・バンドル工程は不要です。

## 収録範囲

- 売却、夕食、翌朝の新聞を会話で描く導入。剣と伝票の画像、300G・260G・残金40Gを表示。
- 4人から3人を編成し、盾崩し・印・大技をつなぐ戦闘。各人2種類の技、SP、かばう、回復薬、レベル、装備の手入れ。
- 伝票の住所から買い手ヒューゴを探す道中3戦と、荷役ゴーレムを止めるボス戦。
- 無料の薬草弁当か、30Gの整備図を選ぶ準備。所持金がなくても無料の選択で進めます。
- 最後に、聖剣の価値を話すか、修理代との相殺を提案する商談。どちらも聖剣を回収し、会話と入手する書類が変わります。
- 初回の会話、既読スキップ、手帳での振り返り、章クリア、回収した聖剣の表示、ボスとの試運転。
- 行動ごとの保存、戦闘・会話途中の再開、正常なバックアップからの復旧、スマホ縦横画面とセーフエリア。

第一章では剣の回収までを扱います。1億Gの受け取りには王都での鑑定が必要で、王都編は未収録です。実際の所持金に1億Gを加える演出は行っていません。

## 通常と戦闘の絵

通常のタイトル・会話・拠点・仲間・装備には、等身の高いアニメ調の立ち絵を使用します。`*-normal-portrait.webp`、`*-normal-body.webp`、`*-normal-face.webp` がその素材です。

戦闘のキャラ・ステータス・戦闘中の回復選択には別のSD素材を使用します。`*-body.webp`、`*-attack.webp`、`*-face.webp` は戦闘用です。同じ服と髪色を保ち、武器を握った絵の構え・攻撃フレームを使い分けます。

素材は制作時に生成したオリジナル画像です。配布用WebPと原画の記録を `assets/` に保持しています。`tools/prepare_assets.py` はSD素材用、`tools/prepare_story_assets.py` は等身の高い立ち絵・店内・新聞・聖剣・新ボスの技術的な切り出し用です。原画PNGは開発環境に保持し、この処理はゲームの起動に不要です。

## 会話の表情

会話では `#story-character` の画像を丸ごと交換し、常に完成した立ち絵を一枚だけ表示します。旧方式の頭部・首・襟・手のマスクや合成レイヤーは使いません。5人それぞれに笑顔・驚き・困り顔・真剣の計20枚を用意し、通常の表情とヒューゴの笑いポーズも使います。

視線は極端な横目や細すぎる半目を避け、話し相手を見る位置に整えています。アッシュの笑顔は歯を大きくむき出す表情から、目を開けた穏やかな笑顔へ変更。リネの丸い頬・大きな琥珀色の目に対して、ノアは長めの輪郭・直線的な眉・細めの緑の瞳・長めの鼻を持つ顔に描き直しました。ノアの通常メニュー画像も同じ新しい絵から切り出します。

会話データの `expression` と任意の `reaction: {at, expression}` で演技を指定します。新聞の「1億G」でリネが驚く場面と、報酬を話してしまい「——あ」で気づくアッシュの場面に対応。一括表示でも同じ最終表情になります。

完成した画像は `assets/portraits/`、制作記録は同フォルダーの `provenance.json`、切り出しは `tools/prepare_expressions.py`。処理は完成した二人並びの原画を分割し、サイズをそろえてWebPへ保存するだけです。旧 `assets/expressions/` は以前のページとの互換性のため残しますが、現在のゲームは読み込みません。バージョン付きURLと数行先の先読みを使い、開始時に全20枚の読み込みを待ちません。

手帳で既読会話を選び「会話画面で見返す」を押すと再読できます。選択肢を再適用せず、報酬や戦闘、進行の記録を変えません。

## 音

効果音とBGMはブラウザ内の Web Audio で合成します。音源ファイルや外部の音楽APIは使いません。`music.js` が原曲の旋律を残した3曲の楽譜と音色を持ち、`audio.js` が再生・設定・効果音・ジングルを管理します。

古道具屋は柔らかい撥弦風の音と丸い低音、戦闘は柔らかい管楽器風の音、ボスは低音とリズムを強めた音色です。いずれも生楽器の録音ではありません。16小節の前半・応答フレーズで構成し、繰り返しは拠点が約44秒、戦闘が約28秒、ボスが約26秒。拠点の細かな打音と常時の揺れを減らし、会話中はBGMを下げます。異なる曲は独立した音量ノードでフェードさせ、会話の文章送りでは曲を再開しません。勝敗・章クリアのジングル中もBGMを抑えます。

効果音は斬撃・矢・光・落星・盾崩し・被ダメージ・回復・かばう・行動中断・ためる・ボタン、ジングルは勝利・敗北・章クリアとレベルアップです。設定の「効果音」「BGM」で個別に切れ、設定は既存の `sword-sale-audio` に保存します。終了した音源ノードを切り離し、ミュート時には音楽のスケジューラーも停止します。

最初のタップで音を開始し、画面を離れると停止します。iPhoneのマナーモードへの既存対応として、タップ時に無音のメディアを再生し、対応する環境では `navigator.audioSession` を `playback` にします。音楽と効果音を両方切った時にはその無音メディアも止めます。実機の音量やマナーモードでの再生確認は未実施です。

## 構成

- `data.js`：人物、NPC、技、ステージ、会話、場面・小道具、戦闘前後の会話の対応。
- `expressions.js` / `portraits.js`：完成した立ち絵の参照、文章途中の表情判定、読み込み・一枚だけの表示。
- `core.js`：戦闘、進行、準備と商談の選択、保存データの検証。
- `game.js`：画面、操作、画像の使い分け、保存、演出。
- `music.js` / `audio.js`：楽譜・音色、場面切り替え、音量、ユーザー操作後の再生、音の設定。
- `styles.css`：スマホ向けUIと会話の小道具表示。

新しい物語の保存キーは `sword-sale-v1`。旧作の `tomori-journey-v1` には書き込まず、既存記録を保持します。ボイス、オンライン対戦、端末間の同期はありません。実行時の画像生成API呼び出しもありません。

## 検証

```sh
node --test tomori/tools/core.test.cjs tomori/tools/portraits.test.cjs tomori/tools/music.test.cjs
```

ゲームルール13件：連携、複数ヒット、かばう、無効操作、保存、報酬、全4編成、準備2種×商談2種の完結、無資金時の進行、商談の条件、会話参照の検証。

表情判定・不正な指定の復旧・会話と素材参照の整合性・アッシュの反応・読み込み競合・代替画像・再表示は追加の7件で確認します。

音の3件では、音名・音高の計算、楽譜の範囲・旋律の重複・和音の参照、後半の応答フレーズを検証します。

PlaywrightのPythonパッケージとChromiumがある環境では、サーバー起動後に次を実行できます。

```sh
python3 tomori/tools/browser_check.py --url http://localhost:8006/tomori/
python3 tomori/tools/expression_browser_check.py --url http://localhost:8006/tomori/
python3 tomori/tools/audio_browser_check.py --url http://localhost:8006/tomori/
```

表情のブラウザ検証では、20枚の完成画像、常に一枚だけの人物表示、旧頭部やマスクへの通信がないこと、文章途中の反応、途中再開、縦横画面、進行を変えない会話再読を確認します。顔や手の見た目は、実際の会話画面を拡大した画像で目視確認します。

通常立ち絵とSDの使い分け、初回会話から両方の商談へのクリア、途中再開、強化、手帳、再戦、旧作保存の保持をブラウザ上で確認します。画面サイズは320×568、390×844、430×932、768×1024、844×390、1280×900。iPhone/Android実機でのSafari/Chromeの確認は未実施です。

音のブラウザ検証にはnumpyも必要です。実際の楽譜と再生エンジンをOfflineAudioContextで全曲一周分出力し、音切れ・ピーク・音源ノード終了・会話中の減音・曲の切り替え・ミュートと復帰を確認します。実際のページの設定保存と、ボス戦から結果画面への切り替えも確認します。試聴用WAVは指定した検証出力フォルダーだけに書き出し、配信するゲームには含めません。
