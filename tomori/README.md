# 勇者の剣、売りました。

昨日300Gで売った剣が、今日1億Gになっていた。代金は四人の夕食へ。古道具屋リネたちが買い手を追いかけ、聖剣を取り戻すコマンドRPGです。第一章「食べた300G」を収録しています。

## 起動

リポジトリのルートで `python3 -m http.server 8006` を実行し、`http://localhost:8006/tomori/` を開きます。外部ライブラリ・バックエンド・バンドル工程は不要です。

## 収録範囲

- 売却、夕食、翌朝の新聞を会話で描く導入。剣と伝票の画像、300G・260G・残金40Gを表示。
- 4人から3人を編成し、盾崩し・印・大技をつなぐ戦闘。各人2種類の技、SP、かばう、回復薬、レベル、装備の手入れ。
- 伝票の住所から買い手ヒューゴを探す道中3戦と、荷役ゴーレムを止めるボス戦。
- 無料の薬草弁当か、30Gの整備図を選ぶ準備。所持金がなくても無料の選択で進めます。
- 最後に、聖剣の価値を話すか、修理代との相殺を提案する商談。どちらも聖剣を回収し、会話と入手する書類が変わります。
- 初回の会話、既読スキップ、手帳での振り返り、章クリア、回収した聖剣の表示、ボスとの試運転。
- 行動ごとの保存、戦闘・会話途中の再開、正常なバックアップからの復旧、スマホ縦横画面とセーフエリア。

第一章では剣の回収までを扱います。1億Gの受け取りには王都での鑑定が必要で、王都編は未収録です。実際の所持金に1億Gを加える演出は行っていません。

## 通常と戦闘の絵

通常のタイトル・会話・拠点・仲間・装備には、等身の高いアニメ調の立ち絵を使用します。`*-normal-portrait.webp`、`*-normal-body.webp`、`*-normal-face.webp` がその素材です。

戦闘のキャラ・ステータス・戦闘中の回復選択には別のSD素材を使用します。`*-body.webp`、`*-attack.webp`、`*-face.webp` は戦闘用です。同じ服と髪色を保ち、武器を握った絵の構え・攻撃フレームを使い分けます。

素材は制作時に生成したオリジナル画像です。配布用WebPと原画の記録を `assets/` に保持しています。`tools/prepare_assets.py` はSD素材用、`tools/prepare_story_assets.py` は等身の高い立ち絵・店内・新聞・聖剣・新ボスの技術的な切り出し用です。原画PNGは開発環境に保持し、この処理はゲームの起動に不要です。

## 会話の表情

リネ・アッシュ・ノア・フィン・ヒューゴに、笑顔・驚き・困り顔・真剣の20差分を収録。元の立ち絵を固定し、登録座標に頭部の差分を重ねます。衣装と体を描き直さず、元のシルエットのマスクと首元のぼかしでつなぎます。ヒューゴの笑いポーズは既存画像を使います。

同じ笑顔の形を共用せず、リネは目を開けた商売用の笑み、アッシュは歯を見せる大きな笑い、ノアは片口角と横目、フィンは視線を落とした控えめな微笑み、ヒューゴは年齢の出る頬と眉の動きで描き分けています。`expressions.js` の人物別 `labels` に演技の意味を記録します。仲間への素直な笑顔では元の立ち絵も使い、場面に合わせて演技を選びます。

会話データの `expression` と、任意の `reaction: {at, expression}` で演技を指定します。新聞の「1億G」が文字送りで現れると、リネが驚く表情へ切り替わります。アッシュが報酬の額を口にしたあと「——あ」で気づく場面でも、笑顔から気まずい表情へ切り替わります。一括表示も対応。頭部の改訂にはバージョン付きURLを使い、以前の画像がキャッシュに残っていても新しい演技を読み込みます。必要な表情を数行先まで先読みし、全差分の読み込みを開始時に待ちません。頭部素材は `assets/expressions/`、切り出しの記録は `provenance.json`、再生成原画の技術的な切り出しは `tools/prepare_expressions.py` です。

手帳で既読会話を選び「会話画面で見返す」を押すと、立ち絵と表情つきで再読できます。選択肢を再適用せず、報酬や戦闘、進行の記録を変えません。

## 音

効果音とBGMは `audio.js` が Web Audio で合成します。音源ファイルはありません。BGMは古道具屋（拠点・会話・タイトル・結果）、道中の戦闘、ボス戦の3曲で、画面に合わせて切り替えます。効果音は斬撃・矢・光・落星・盾崩し・被ダメージ・回復・かばう・行動中断・ためる・ボタン、ジングルは勝利・敗北・章クリアとレベルアップです。スマホのブラウザは最初のタップまで音を出せないため、タップした時点で鳴り始めます。設定の「効果音」「BGM」で個別に切れ、設定は `sword-sale-audio` に保存します。画面を離れると止まります。

## 構成

- `data.js`：人物、NPC、技、ステージ、会話、場面・小道具、戦闘前後の会話の対応。
- `expressions.js` / `portraits.js`：差分画像の座標、文章途中の表情判定、読み込み・表示。
- `core.js`：戦闘、進行、準備と商談の選択、保存データの検証。
- `game.js`：画面、操作、画像の使い分け、保存、演出。
- `styles.css`：スマホ向けUIと会話の小道具表示。

新しい物語の保存キーは `sword-sale-v1`。旧作の `tomori-journey-v1` には書き込まず、既存記録を保持します。ボイス、オンライン対戦、端末間の同期はありません。実行時の画像生成API呼び出しもありません。

## 検証

```sh
node --test tomori/tools/core.test.cjs tomori/tools/portraits.test.cjs
```

ゲームルール13件：連携、複数ヒット、かばう、無効操作、保存、報酬、全4編成、準備2種×商談2種の完結、無資金時の進行、商談の条件、会話参照の検証。

表情判定・不正な指定の復旧・会話と素材参照の整合性・アッシュの反応は追加の4件で確認します。

PlaywrightのPythonパッケージとChromiumがある環境では、サーバー起動後に次を実行できます。

```sh
python3 tomori/tools/browser_check.py --url http://localhost:8006/tomori/
python3 tomori/tools/expression_browser_check.py --url http://localhost:8006/tomori/
```

表情のブラウザ検証はPillowも使用します。20差分の表示、体の画像の維持、文章途中の反応、途中再開、縦横画面での位置合わせ、進行を変えない会話再読を検証します。

通常立ち絵とSDの使い分け、初回会話から両方の商談へのクリア、途中再開、強化、手帳、再戦、旧作保存の保持をブラウザ上で確認します。画面サイズは320×568、390×844、430×932、768×1024、844×390、1280×900。iPhone/Android実機でのSafari/Chromeの確認は未実施です。
